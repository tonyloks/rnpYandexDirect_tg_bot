## Детализация по эпику

### 1) Базовая инфраструктура репозитория

**Задачи**

* Инициализировать `pyproject.toml` (poetry), базовые зависимости.
* Настроить `pre-commit` (ruff/black/isort; по возможности mypy).
* Сгенерировать дерево каталогов (из ТЗ) и пустые модули.
* Добавить `.env.example`, `.gitignore`, первичный `README.md`.
* CI: GitHub Actions — шаги `lint + tests + docker build`.

**Результат**

* Репозиторий собирается и линтится в CI.

**DoD**

* `poetry install` проходит, `pre-commit run -a` чисто, CI зелёный.

---

### 2) Конфигурация/Bootstrap процесса (DI, запуск, healthz)

**Задачи**

* `app/config.py`: Pydantic Settings, чтение ENV/валидация, `APP_TIMEZONE`, режимы доступа.
* `app/api/health.py`: FastAPI эндпоинт `/healthz` (200 ОК).
* `app/main.py`: настройка логов, БД, `Dispatcher`, монтирование FastAPI, апгрейд миграций на старте, запуск long polling.

**Результат**

* Единая точка входа: `python -m app.main`.

**DoD**

* Локальный запуск возвращает 200 на `/healthz`, бот стартует без ошибок.

---

### 3) База данных: миграции и репозитории

**Задачи**

* Alembic baseline + миграции с DDL из ТЗ.
* `app/infra/db.py`: async engine/session, helper для `alembic upgrade`.
* `app/infra/repos.py`: CRUD для `users`, `yd_accounts`, `schedules`, `allowed_users`, (`cache_*`).
* Индексы и уникальные ключи по спецификации.

**Результат**

* Схема БД соответствует ТЗ, есть слой репозиториев.

**DoD**

* `alembic upgrade head` успешно, smoke‑тесты CRUD проходят.

---

### 4) Криптография токенов

**Задачи**

* `app/infra/crypto.py`: реализация AES‑GCM/Fernet (через `cryptography`).
* Функции `encrypt_token`/`decrypt_token`, хранение `nonce`, base64‑ключ `APP_KMS_KEY` из ENV.
* Маскирование секретов в логах.

**Результат**

* Безопасное хранение токенов Я.Директ в БД.

**DoD**

* Unit‑тесты: корректность шифрования/дешифрования; ключ берётся из ENV.

---

### 5) Интеграция с Я.Директ (адаптер)

**Задачи**

* `app/infra/yd_adapter.py`: `YDAdapter` с таймаутами (10–15s) и backoff‑ретраями (429/5xx, 0.5→1.5s с джиттером).
* Методы `get_budgets(acc)` и `get_stats(acc, period, goals)`.
* Обработка частичных ошибок — собственные исключения.

**Результат**

* Тонкая обёртка над предоставленным модулем Я.Директа.

**DoD**

* Интеграционные тесты с мок‑клиентом: успех/ошибки/таймауты/ретраи.

---

### 6) Доменный слой: периоды/DTO/форматирование

**Задачи**

* `app/domain/periods.py`: today/yesterday/last_week, TZ‑корректно.
* `app/domain/models.py`: DTO для Accounts/Stats/Budgets.
* `app/bot/formatting.py`: строки по аккаунтам + «ИТОГО», округления и локализация.

**Результат**

* Единая бизнес‑логика периодов и форматирования.

**DoD**

* Unit‑тесты: периоды для разных TZ, корректный пример сводки.

---

### 7) Каркас бота: роутеры, клавиатуры, middleware доступа

**Задачи**

* `app/bot/router.py`: корневой Router, регистрация саб‑роутеров.
* `app/bot/keyboards.py`: главное меню и inline‑кнопки периодов.
* `app/bot/middlewares.py`: `AccessMiddleware` (owner‑only/allowlist, запрет групп), лог входящих апдейтов.
* Handlers: `/start`, `/help`, `/privacy`.

**Результат**

* Каркас взаимодействия и авторизации пользователей.

**DoD**

* В приватном чате владелец и allowlist проходят; прочие получают отказ с подсказкой.

---

### 8) Потоки подключения: `/connect` + `/accounts`

**Задачи**

* `/connect` (FSM): login → token → goals CSV → account_id? → тестовый `getBudgets` → сохранение (шифруя токен) → `last_ok_at`.
* Парсинг `goals_csv` → список; валидация.
* `/accounts`: список, деактивация/удаление; уникальность `(tg_user_id, login, coalesce(account_id,''))`.

**Результат**

* Управление несколькими аккаунтами Я.Директа на пользователя.

**DoD**

* Happy‑path и ошибки (невалидный токен/уникальность) покрыты; запись создаётся; `last_ok_at` выставляется.

---

### 9) Статистика и бюджеты: `/stats` и `/budgets`

**Задачи**

* `/stats`: выбор периода (Сегодня/Вчера/7 дней), параллельные `getStats`+`getBudgets`, агрегация и итог, один ответ.
* `/budgets`: суммарные бюджеты по всем активным аккаунтам, один ответ.
* Частичные ошибки помечать ⚠️ и исключать из «ИТОГО». Сообщение «нет подключённых аккаунтов» — явное.

**Результат**

* Основная пользовательская ценность: сводки и бюджеты по запросу.

**DoD**

* Сообщения соответствуют примерам из ТЗ; ошибки отдельных аккаунтов не ломают итог.

---

### 10) Планировщик: `/schedule` + APScheduler‑джоба

**Задачи**

* Таблица `schedules`: repo CRUD и уникальность `(tg_user_id, kind)`.
* `app/sched/scheduler.py`: инициализация APScheduler, загрузка enabled‑джоб при старте, регистрация `send_daily_today_stats`.
* `/schedule`: включить (время, дефолт 09:00), выключить, статус; учёт TZ из записи.

**Результат**

* Ежедневная рассылка «стата+бюджеты за сегодня».

**DoD**

* Джоба выполняется по TZ, переживает рестарт процесса, управляется командами.

---

### 11) Кэширование (опционально)

**Задачи**

* Таблицы `cache_budgets`, `cache_stats`.
* Встроить кэш в `YDAdapter`: чтение/запись; TTL: budgets 60–120s, stats 1–5m (дольше для yesterday/last_week), инвалидация на изменения.
* Фича‑флаг в конфиге (вкл/выкл).

**Результат**

* Снижение количества внешних вызовов.

**DoD**

* Тесты TTL и инвалидации; наблюдается уменьшение обращений к API.

---

### 12) Логи, обработка ошибок, наблюдаемость

**Задачи**

* `structlog`/`loguru` с JSON‑форматом (timestamp, action, user_id, login/account_id, duration, outcome).
* Глобальные обработчики исключений (бот и web), без утечек секретов.
* `/healthz`: быстрая проверка готовности (опц. ping БД).

**Результат**

* Прозрачная эксплуатация и поддержка.

**DoD**

* Логи структурированы; ошибки/таймауты отражаются; healthcheck зелёный.

## DoD чек‑листы для ключевых потоков

### `/stats`

* [ ] Выбор периода (Сегодня/Вчера/7 дней) работает в `APP_TIMEZONE`.
* [ ] Параллельные вызовы к Я.Директ; таймауты/ретраи соблюдены.
* [ ] Частичные ошибки помечаются ⚠️ и исключаются из «ИТОГО».
* [ ] Сообщение содержит: клики, конверсии, CTR, CPA, расход, сумму бюджетов.

### `/schedule`

* [ ] Создание/обновление единственной daily‑задачи на пользователя.
* [ ] Учёт TZ при выполнении.
* [ ] Перезапуск процесса поднимает enabled‑джобы.

### Безопасность

* [ ] Токены в БД только в зашифрованном виде.
* [ ] Логи без PII/секретов.
* [ ] Режимы `owner-only`/`allowlist` соблюдаются.
* [ ] Групповые чаты запрещены при `ALLOW_GROUP_CHATS=false`.

## Примечания по эксплуатационным сценариям

* Ошибки отдельных аккаунтов не блокируют общую сводку — строка помечается ⚠️ и исключается из итогов.
* Кэш рекомендуется включать при высокой нагрузке или медленном API.
* Для TimeWeb Cloud задокументировать: где задавать ENV/секреты, как смотреть логи контейнера, как выполнять redeploy.
